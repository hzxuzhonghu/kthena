# Kthena 正式发布：让大模型推理，回归云原生的简单与高效

当企业把大模型从 Demo 推向生产，问题往往不是“能不能跑”，而是“如何稳定、如何省钱、如何大规模、如何好用”。Kthena 以 Kubernetes 为底座，以“声明式管控 + 智能路由”为核心，为企业带来云原生、可观测、可进化的 LLM 推理基础设施。

一句话总结：Kthena 让大模型推理像部署微服务一样自然，又像调度高性能计算一样强大。

---

## 为什么是现在，为什么是 Kthena

- 成本压力陡增：模型更大、上下文更长、QPS 更高，GPU/NPU 成为稀缺资源；“靠堆机器”不可持续。
- 体验目标更苛刻：TTFT/TPOT、队列时延、SLO/SLA 都要“看得见、管得住、控得稳”。
- 体系复杂度倍增：多引擎（vLLM、SGLang、Triton…）、多硬件（GPU/NPU/异构）、多拓扑（Prefill/Decode 解耦）、多团队协同，传统脚本/人工粘合已难以为继。

Kthena 从第一天起就选择“云原生 + AI 原语”的组合拳：用 CRD 把模型、路由、服务、扩缩容描述清楚，用控制/数据双平面把可靠性、可观测与性能分治到底，再以插件化的智能路由与调度把吞吐、时延、成本一体化优化。

---

## Kthena 是什么

Kthena 是一个 Kubernetes 原生的大模型推理平台，采用“控制平面 + 数据平面”的双平面架构：

- 控制平面（Kthena Controller Manager）
  - 用一组专门的 CRD 声明式管理模型全生命周期与扩缩容策略
  - 与 Volcano 集成，支持拓扑感知与 Gang 调度，保证分布式推理“成组原子化”落地
  - 支持滚动升级、健康态观测与回滚安全阀
- 数据平面（Kthena Router）
  - 作为推理入口，完成认证鉴权/限流/公平队列
  - 基于可插拔调度插件的“模型感知路由”，对接 vLLM、SGLang 等主流引擎
  - 原生支持 Prefill/Decode 解耦与 PD Group 感知分发，保证吞吐与时延的平衡

---

## 架构一图流（要点）

- 原生 CRD：ModelBooster、ModelServing、ModelServer、ModelRoute、AutoScalingPolicy、AutoScalingPolicyBinding
- 控制平面：Model Booster Controller、Model Serving Controller、Autoscaler Controller
- 数据平面：Router（Listener/Filters/Scheduler/Backend/Metrics/Datastore）
- 生态对接：Volcano、Kubernetes Gateway API 推理扩展等

这一结构让“声明式交付 + 智能执行”成为现实：你只需专注模型与策略，其余由 Kthena 自动完成。

## 六大核心能力

### 1) 生产级推理编排（ModelServing）

- Prefill-Decode 解耦：预填与解码角色拆分、独立伸缩，打满硬件利用率
- 双 Pod 模型（Entry/Worker）：既保证接入吞吐，又兜住算力密集
- 多并行范式：TP/PP 等并行模式灵活配置
- 拓扑感知 + Gang 调度：同组同域、全体就绪再调度，避免“半拉子工程”

### 2) 一站式模型上线（ModelBooster）

- 一个 CR 描述模型，自动展开为 ModelRoute/ModelServer/ModelServing/Autoscaling 组合
- 覆盖大多数常见场景，复杂边界可手动细化 CRD

### 3) 智能、模型感知的路由（Kthena Router）

- 插件化调度：最少请求、最小时延、KV Cache 感知、Prefix Cache 感知、LoRA 亲和、GPU Cache 感知、公平调度等
- LoRA 热插拔无中断：路由对 LoRA 适配器状态“心中有数”，流量无缝跟随
- 丰富流量策略：加权/金丝雀发布、令牌级率控、异常自动熔断与回退
- 独立二进制，易于与现有 API Gateway 叠加共存

### 4) 成本驱动的自动扩缩容（Autoscaler）

- 同构伸缩：稳定/突发双模，按业务指标（CPU/GPU/内存/自定义）精准扩缩
- 异构优化：在多引擎/多硬件/多参数组合中按“成本-能力”贪心分配，最大化性价比并降低冷启动抖动

### 5) 多引擎与异构硬件

- 引擎：vLLM、SGLang、Triton/TGI 等，统一抽象、统一指标
- 硬件：GPU/NPU 等异构可混部，配合异构 Autoscaling 做成本与 SLO 的动态平衡

### 6) 网络与公平性内置

- 拓扑与亲和：同组同域、带宽友好
- 公平队列：多租户一致体验，防止“饿死”
- 速率/令牌限流：按用户/模型/角色（如 decode）精细化

## 性能与实证

基于 Kthena Router 的调度插件架构，在长系统提示场景（如 4096 tokens）下，采用“KV Cache 感知 + 最少请求”策略相较随机基线：

- 吞吐可提升约 2.73 倍
- TTFT 降低约 73.5%
- 端到端时延降低超过 60%

短提示场景差距会收敛，但在多轮对话、模板化生成、前缀高度相似的业务中，Cache 感知策略优势明显。实际收益与模型规模、Prompt长短、硬件紧密相关，但“按需组合、按场景选型”已被验证有效。

## 与传统方案的差异化优势

- 从“工程粘合”到“声明式平台”：CRD 还原业务意图，控制器持续调和，自动把复杂变简单
- 从“流量盲目”到“模型感知”：路由以 KV/Prefix/LoRA 等语义指标决策，让资源调度围绕业务价值旋转
- 从“静态配方”到“成本优先”：异构 Autoscaling 把“哪台更省钱”纳入一体化求解
- 从“可用即可”到“可观测可治理”：指标、队列、公平、拓扑、金丝雀、回滚全部内建
